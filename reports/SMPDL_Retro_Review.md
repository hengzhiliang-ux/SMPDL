## 3. 案例一：欧几里得素数无限

### 3.1 证明回顾

```text
假设只有有限个素数 p₁, p₂, ..., pₙ。
令 N = p₁p₂...pₙ + 1。
N 不被任何 pᵢ 整除，因此 N 要么本身是素数，要么有新的素因子。
无论哪种情况，都存在一个不在原列表中的素数。
矛盾。故素数无限。
```

### 3.2 S/M/P × D/L 审查

#### S*D：语义依存

| 支持元素 | 被支持元素 |
|---|---|
| 假设有限素数 | 构造 N |
| 构造 N | N 不被任何 pᵢ 整除 |
| N 不被任何 pᵢ 整除 | N 有新素因子 |
| N 有新素因子 | 矛盾 |
| 矛盾 | 素数无限 |

**S*D：✅ 依存链闭合。**

#### S*L：语义逻辑结构

| 检查点 | 状态 | 说明 |
|---|---|---|
| 量词 | ✅ | ∀ 有限素数集合；∃ 新素数。 |
| 反证法 | ✅ | 假设 ¬P，推出矛盾，得到 P。 |
| 「不被任何 pᵢ 整除」→「有新素因子」 | ✅ | 自然语言隐含了算术基本定理，在初等数论语境中可接受。 |

**S*L：✅ 通过。**

#### M*D：数学依存

```
素数定义
    │
    ▼
整除性
    │
    ▼
带余除法 / 欧几里得引理
    │
    ▼
N = ∏pᵢ + 1 不被任何 pᵢ 整除
    │
    ▼
N 有不在列表中的素因子
    │
    ▼
矛盾 → 素数无限
```

**M*D：✅ 数学依赖图闭合。**

#### M*L：数学逻辑结构

| 检查点 | 状态 | 说明 |
|---|---|---|
| 反证法结构 | ✅ | 假设、推导、矛盾、结论完整。 |
| 存在性推理 | ✅ | N 的存在由构造给出；新素因子由欧几里得引理给出。 |
| 边界 | ✅ | 对 n=1 也成立（N=2 或 3）。 |

**M*L：✅ 通过。**

#### P*D：编程依存

| 检查元素 | 被支持元素 |
|---|---|
| 素数判定函数 | 验证 N 的素性 |
| 大整数库 | 计算 ∏pᵢ + 1 |

**P*D：⚠️ 依赖具体实现，但 trivial。**

#### P*L：编程逻辑结构

| 检查点 | 状态 | 说明 |
|---|---|---|
| 形式化可行性 | ✅ | 可在 Lean/Coq 中完整形式化。 |
| 关键步骤 | ✅ | `not_dvd_of_mod_eq_one` 等引理标准。 |
| 无意外公理 | ✅ | 只需皮亚诺算术。 |

**P*L：✅ 通过。**

### 3.3 跨层映射

## 4. 案例二：所有三角形都是等腰

### 4.1 证明回顾

```text
任取三角形 ABC。
设 AB 边的垂直平分线与 ∠C 的角平分线交于 P。
由 P 在 AB 垂直平分线上，得 PA = PB。
由 P 在 ∠C 角平分线上，向 AC、BC 作垂线 PU、PV，则 PU = PV。
直角三角形 PUA 与 PVB 全等（RHS），故 AU = BV。
直角三角形 PUC 与 PVC 全等，故 CU = CV。
因此 AC = AU + CU = BV + CV = BC。证毕。
```

### 4.2 S/M/P × D/L 审查

#### S*D：语义依存

| 支持元素 | 被支持元素 |
|---|---|
| 任取三角形 ABC | 构造 P |
| P 在垂直平分线上 | PA = PB |
| P 在角平分线上 | PU = PV |
| PU = PV + RHS | AU = BV, CU = CV |
| AU = BV, CU = CV | AC = BC |

**S*D：⚠️ 依存链看起来闭合，但「AC = AU + CU」依赖未声明的几何条件。**

#### S*L：语义逻辑结构

| 检查点 | 状态 | 说明 |
|---|---|---|
| 量词 | ⚠️ | 「任取三角形」= ∀ABC，但未排除退化三角形。 |
| 「AU + CU」的合法性 | ❌ | 加法等式要求 U 在线段 AC 内部，自然语言未显式声明。 |
| 推理规则 | ❌ | 从 AU + CU = AC 到结论，使用了非法的几何位置假设。 |
| 隐喻/跳跃 | ❌ | 步骤 5-6 的等式传递隐藏了关键几何条件。 |

**S*L：❌ 失败。**

#### M*D：数学依存

```
三角形 ABC
    │
    ▼
P = perp_bisector ∩ angle_bisector
    │
    ▼
PA = PB, PU = PV
    │
    ▼
RHS 全等 → AU = BV, CU = CV
    │
    ▼
AC = AU + CU = BV + CV = BC  （断裂）
```

**M*D：⚠️ 数学依赖图在 M9 处断裂。**

#### M*L：数学逻辑结构

| 检查点 | 状态 | 说明 |
|---|---|---|
| 构造合法性 | ✅ | P 点存在。 |
| 全等推理 | ✅ | RHS 全等合法。 |
| 长度加法 | ❌ | `AC = AU + CU` 等价于 U 在 AC 上，这一条件非普遍成立。 |
| 边界/反例 | ❌ | 非等腰三角形中 U 落在延长线上，加法不成立。 |
| 全称推广 | ❌ | 从某配置跳到 ∀ 三角形，边界未覆盖。 |

**M*L：❌ 失败。**

#### P*D：编程依存

| 支持元素 | 被支持元素 |
|---|---|
| 三角形定义 | 距离函数 |
| 距离函数 | 全等判定 |
| 全等判定 | 长度等式 |
| 长度等式 | 加法等式（断裂） |

**P*D：⚠️ 程序依赖在 P11 处断裂。**

#### P*L：编程逻辑结构

| 检查点 | 状态 | 说明 |
|---|---|---|
| 形式化可行性 | ❌ | 核心加法步骤 `dist A C = dist A U + dist U C` 无法证明。 |
| 缺少假设 | ❌ | `between A U C` 未在前提中出现。 |
| Lean 报错 | ❌ | 会留下不可填充的 `sorry`。 |

**P*L：❌ 失败。**

### 4.3 跨层映射

| 映射 | 状态 | 说明 |
|---|---|---|
| S*D → M*D | ❌ | S8 的「AU + CU」在 M 层需要额外条件。 |
| S*L → M*L | ❌ | S 层的自然语言加法与 M 层的 on-segment 条件不对应。 |
| M*D → P*D | ❌ | M9 的断裂在 P11 复现。 |
| M*L → P*L | ❌ | M 层缺失的条件在 P 层表现为 `sorry`。 |

### 4.4 与旧框架对比

| 维度 | 旧 SMPL 依存发现 | 新 S/M/P × D/L 发现 |
|---|---|---|
| 断裂点 | S8/M9/P11：长度加法 | 同上，但更明确：S*L 的推理规则失败、M*L 的边界失败、P*L 的 `sorry` |
| 根因 | 未显式陈述的 on-segment / betweenness | 同上，但 L 维度细化：同时违反量词、假设、推理规则、结构、边界 |
| 修复方向 | 增加 on-segment 条件或限制三角形类型 | 更清晰：S*L 需显式声明位置；M*L 需分类讨论；P*L 需加入 `between` 假设 |

## 5. 案例三：Kempe 四色定理证明

### 5.1 证明回顾

```text
最小反例法 + 不可避免集 + 可约化构形。
四种构形：digon, triangle, quadrilateral, pentagon。
digon/triangle/quadrilateral 可约化。
pentagon 通过两次 Kempe 链颜色互换可约化。
因此最小反例不存在。
```

### 5.2 S/M/P × D/L 审查

#### S*D：语义依存

| 支持元素 | 被支持元素 |
|---|---|
| Euler 公式 | 存在低度顶点 |
| 存在低度顶点 | 四种构形不可避免 |
| digon/triangle 可约化 | 简单情形解决 |
| quadrilateral 可约化 | 一次 Kempe 互换解决 |
| pentagon 可约化 | 两次 Kempe 互换解决（断裂） |
| 所有构形可约化 | 最小反例不存在 |

**S*D：⚠️ 步骤 5 的依存建立在未声明的前提上。**

#### S*L：语义逻辑结构

| 检查点 | 状态 | 说明 |
|---|---|---|
| 量词 | ✅ | ∀ 平面图。 |
| 「同时两次互换」的语义 | ❌ | 未说明两次操作是否相互干扰。 |
| 隐喻 | ❌ | 「互换」暗示可逆且独立，但未证明。 |
| 结构完整性 | ❌ | 缺少「两次互换后仍为合法着色」的论证。 |

**S*L：❌ 失败。**

#### M*D：数学依存

```
Euler 公式
    │
    ▼
不可避免集
    │
    ├── digon/triangle ──→ 直接可约化
    │
    ├── quadrilateral ──→ 一次 Kempe 互换
    │
    └── pentagon ──→ 两次 Kempe 互换（断裂）
```

**M*D：⚠️ pentagon 分支的依赖缺少关键引理。**

#### M*L：数学逻辑结构

| 检查点 | 状态 | 说明 |
|---|---|---|
| 反证法结构 | ✅ | 最小反例不存在 → 定理成立。 |
| 分情况穷尽 | ✅ | 四种构形覆盖度数 ≤5。 |
| 单次 Kempe 互换 | ✅ | 合法。 |
| 两次 Kempe 互换 | ❌ | 把单次操作规则非法推广到两次同时操作。 |
| 边界/反例 | ❌ | 未考虑 Kempe 链相交的 degree-5 配置（Heawood 反例）。 |
| 假设管理 | ❌ | 把步骤 4 的合法性默认迁移到步骤 5。 |

**M*L：❌ 失败。**

#### P*D：编程依存

| 支持元素 | 被支持元素 |
|---|---|
| 图着色定义 | 合法着色判定 |
| Kempe 链算法 | 一次互换实现 |
| 两次互换实现 | pentagon 可约化判定（断裂） |

**P*D：⚠️ 两次互换的实现缺少合法着色的保证。**

#### P*L：编程逻辑结构

| 检查点 | 状态 | 说明 |
|---|---|---|
| 一次互换 | ✅ | 可证明保持合法着色。 |
| 两次互换复合 | ❌ | `swap chain_RG (swap chain_BY C)` 无法保证 `ProperColoring`。 |
| 缺少引理 | ❌ | 不存在「两次 Kempe 链不相交」的证明。 |
| Lean 报错 | ❌ | 会留下不可填充的 `sorry`。 |

**P*L：❌ 失败。**

### 5.3 跨层映射

| 映射 | 状态 | 说明 |
|---|---|---|
| S*D → M*D | ❌ | S5 的「两次互换」在 M 层需要额外条件。 |
| S*L → M*L | ❌ | S 层的「同时互换」在 M 层无对应结构保证。 |
| M*D → P*D | ❌ | M 层缺少的引理在 P 层表现为实现断裂。 |
| M*L → P*L | ❌ | M 层的非法推广在 P 层表现为 `sorry`。 |

### 5.4 与旧框架对比

| 维度 | 旧 S/M/P 发现 | 新 S/M/P × D/L 发现 |
|---|---|---|
| 断裂点 | S5：两次 Kempe 互换 | 同上 |
| 根因 | 未声明「两条 Kempe 链不相交」 | 同上，但 L 维度细化：量词推广、假设迁移、推理规则、结构完整性、边界遗漏同时失败 |
| 修复方向 | 增加链不相交引理或承认五色定理 | 更清晰：M*L 需增加组合条件；P*L 需先证明复合操作合法性 |

## 6. 案例四：Riemann 假设诊断

RH 不是证明，而是未解猜想。因此 S*D/S*L/P*D/P*L 不适用（没有完整证明的语义/编程结构）。但 M*D/M*L 以及跨层映射仍可诊断。

```
    ▼
解析延拓
    │
    ▼

    │
    ▼
零点分布
    │
    ▼
「所有非平凡零点都在临界线上」
    │

```

**M*D：⚠️ 依赖图在「全称结论」处缺少桥梁。**

### 6.3 M*L：数学逻辑结构

| 检查点 | 状态 | 说明 |

## 7. 综合对比：旧框架 vs 新框架

### 7.1 新框架复现旧发现的能力

| 对象 | 旧框架核心发现 | 新框架是否复现 | 额外细化 |
|---|---|---|---|
| 欧几里得 | 完全通过，S4 隐性假设需显式化 | ✅ | 明确该问题落在 M*L 的存在性推理 |
| 等腰三角形 | S8/M9/P11 断裂，缺少 on-segment | ✅ | 同时违反 S*L/M*L/P*L，细化到 5 个 L 纪律 |
| Kempe | S5 两次互换隐性前提 | ✅ | 细化到量词、假设、规则、结构、边界 |
| RH | M 层缺口 | ✅ | 明确为 M*L 的非法全称推广 + 等价循环 + transfer 失败 |

### 7.2 新框架的增益

1. **统一语言**：所有分析都使用 S/M/P × D/L 六类审查，便于横向比较。
2. **更细的逻辑诊断**：旧框架说「M 层失败」，新框架能说「M*L 中推理规则非法推广 + 边界遗漏」。
3. **跨层映射显性化**：旧框架的「跨层同构强度」被拆分为 D 跨层映射和 L 跨层映射，更精确。
4. **研究级证明适用**：Appel–Haken 案例显示新框架能处理「正确但形式化有缺口」的证明。

### 7.3 新框架的局限

1. **输出更复杂**：每个对象需要填 8 个格子（6 类审查 + 2 个跨层映射）。
2. **对简单证明过重**：欧几里得素数无限用新框架分析显得冗余。
3. **仍需人工判断**：L 维度中的「隐喻是否严格化」「边界是否覆盖」难以完全自动化。

## 8. 建议的审查流程

基于四个案例的试验，建议采用分层流程：

```text
Step 1: S*D 快速依存扫描
    └── 若断裂 → 进入定位修复
    └── 若通过 → Step 2

Step 2: S*L 语义逻辑纪律扫描
    └── 若 FAIL → 明确量词/隐喻/叙事问题
    └── 若通过 → Step 3

Step 3: M*D 数学依赖图
    └── 若断裂 → 补全引理/定义
    └── 若通过 → Step 4

Step 4: M*L 数学逻辑结构
    └── 若 FAIL → 检查推理规则/边界/反例
    └── 若通过 → Step 5

Step 5: P*D 形式化依赖
    └── 若断裂 → 修复代码/引理引用
    └── 若通过 → Step 6

Step 6: P*L 形式化逻辑结构
    └── 若 FAIL → 根据 Lean/Coq 报错回溯 M*L 或 S*L
    └── 若通过 → Step 7

Step 7: D 跨层映射 + L 跨层映射
    └── 若断裂 → 统一 S/M/P 三层的依存与逻辑结构
    └── 若通过 → 证明完全通过
```

## 9. 结论

> **S/M/P × D/L 统一框架成功复现并细化了此前四个案例的所有核心发现。**

- **欧几里得**：完全通过，仅在 P*D 层面有 trivial 依赖。
- **等腰三角形**：S*L / M*L / P*L 同时失败，根因是 on-segment 条件缺失。
- **Kempe**：S*L / M*L / P*L 同时失败，根因是单次→两次 Kempe 互换的非法推广。
- **RH**：核心缺口在 M*L，表现为无法把局部/统计信息合法推广到全称结论。

新框架比旧框架提供了**更精确的诊断语言**和**更统一的比较基础**。建议后续所有证明审查都按 S/M/P × D/L 矩阵输出。
