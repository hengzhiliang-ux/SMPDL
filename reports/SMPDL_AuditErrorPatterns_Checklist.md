## 〇、总则

审计者（LLM）与被审计对象（LLM 证明）共享程序性知识盲区（B4 Q3 失败模式同型，Day-1 自审错误率 13% = 2/15）。本清单是审计者的「自我sorry检查」——**审计输出前逐项过，复核时逐项扫**。

## 一、检索类陷阱（RETrieval）

### RET-1 · 关键词单扫陷阱 ⭐已造成错误
- **案例**：310 定案「零 CFSG 依赖」——只搜缩写 "CFSG"（0 hits），实际论文以全称引用 GLS《The Classification of the Finite Simple Groups》[10] 且 §9 处理 PSL₄(5)；
- **规则**：一切「零依赖/无引用/不含 X」类断言，必须**三重扫**：缩写 + 全称 + 标准文献作者名（如 CFSG / Classification of Finite Simple Groups / Gorenstein–Lyons–Solomon）；
- **检查动作**：审计文档中每个「0 hits」结论旁必须列出检索过的全部关键词。

### RET-2 · 归一化字符陷阱 ⭐已造成错误
- **案例**：三向交叉筛选三处误放行——016 Zilber–Pink（en-dash –）、004 Hilbert's（右单引号 '）、056 Kähler（变音符 ä）；
- **规则**：跨文档标题匹配前必须归一化：en-dash/em-dash → 空格、' ' ' → 空、变音符折叠（NFKD + strip combining）；匹配后仍需抽查命中结果；
- **检查动作**：任何「未匹配/已排除」清单抽样 5% 人工复核。

### RET-3 · PDF 断词陷阱 ⭐已造成险情
- **案例**：300 的 "Conjec- ture 2.8(2)"（pypdf 提取连字符断行）——初检正则漏报，幸原结论正确；
- **规则**：PDF 文本检索模式必须容忍断词：`Conjec.{0,3}ture`、跨行空格 `\s*`；
- **检查动作**：检索 0 hits 且预期应有命中时，先试断词容错模式再下结论。

## 二、直觉类陷阱（INTuition）

### INT-1 · 方向/单调性心算捷径 ⭐已造成错误
- **案例**：225-R3「c→0 乘数→0（涨落冻结）」——实际 σ²=1/arcsin(c/2) 在 c→0 时 → +∞ 发散（临界行为正确表现）；一行 Python 代点即可避免；
- **规则**：**一切方向/极限/单调性判断必须数值代点**（至少 3 点：端点、中点、趋近点）；
- **检查动作**：审计文档中每个「→0/→∞/递增/递减/相容」断言旁标数值验证值。

### INT-2 · 物理直觉错配
- **案例**（同上 225）：把 c→0（反铁电临界点，涨落增强）与冻结相（c>2 端，涨落受抑）的直觉互换；
- **规则**：相图/参数空间的「哪个端是什么相」必须先显式定位再谈直觉；
- **检查动作**：涉及相变/临界类内容，先写出参数区间的相标签表。

### INT-3 · 置换/对称性误读
- **案例风险**：量词顺序（∀∃ vs ∃∀）、共变/反变方向、左/右作用——B4 轮 Q1 失误（对象构成律判成行为律）即句法-语义错配同型；
- **规则**：陈述转写时保持量词原文顺序，不做记忆重组。

## 三、引用类陷阱（CITation）

### CIT-1 · 记忆引用未分级 ⭐已造成缺陷
- **案例**：225 定案引「Kenyon dimer 线 4/π」来自记忆未开文献——数值自洽（σ²(√2)=4/π 复算确认）但置信等级未标；
- **规则**：外部对照分两级——**文献级**（已打开原文核对）/ **记忆级**（数值自洽但未开文献）；判定表必须标注；
- **检查动作**：定案报告中每个外部常数/定理引用标注 [文献级] 或 [记忆级]。

### CIT-2 · 编号信任
- **案例风险**：论文自引编号（PV15 Conj 2.8(2)、GLR 2508.02237、Hanke [18]）——编号真实 ≠ 内容如引；本轮未打开外部原文的编号全部是潜在风险位；
- **规则**：定案级（🟢）结论所依赖的外部编号必须开原文；🟡 以下可暂缓。

---

## 四、判定类陷阱（VERdict）

### VER-1 · 包装层-本体层混淆 ⭐已造成假阳性
- **案例**：335「称号偏移红旗」——CONTENTS.md 族页写「resolving the Gromov–Lawson conjecture」，我判为称号传递未披露；复核发现论文本体 §1.2 桥接完整（Cor 1.2 正式命名 + Thm 1.3 全证）。**失真在族页包装，不在论文本体**；
- **规则**：否定性判定（红旗/弱化/缺失）必须区分作用层级：族页包装 vs 论文本体 vs 定理陈述 vs 证明体——「包装失真 ≠ 本体缺陷」；
- **检查动作**：每个红旗判定旁注明「检查过的最深层级」。

### VER-2 · 加分项反向依赖
- **案例**：310 曾把「零 CFSG」列为正面加分项——加分项错误时损害大于中性项错误（ reviewer 信任锚）；
- **规则**：加分项的标准高于中性项：加分断言必须双重验证（三重扫 + 数值/原文核对）。

### VER-3 · 判定粒度不齐
- **案例风险**：60 份旧审计是 README 级（摘要层），20 份新审计是 PDF 级混合——两批判定不可直接合并统计（层间不可比）；
- **规则**：判定表必须带审计层级标签：L0 摘要级 / L1 PDF 陈述级 / L2 PDF 证明级 / L3 机器验证级。

## 五、成本类陷阱（COSst）

### COS-1 · 验证成本低估 ⭐已造成错误
- **案例**：178「LAPACK 谱验证十分钟级」——实际论文无验证代码，外部复算需从论文规格重新实现 85 页四阶段管线 = 天级工程；
- **规则**：「X 分钟可验证」断言的前提清单必须显式：是否已有代码/显式数据/工具链；
- **检查动作**：成本承诺分三级——分钟级（有现成可运行物）/ 小时级（需写胶水代码）/ 天级（需重新实现）。

### COS-2 · 大库操作超时低估
- **案例**：全库 git clone 挂 11 分钟死、zip 下载 120s 截断、tree API 截断（62,574 文件）——多次网络成本误判；
- **规则**：>100MB 或 >5 万文件的操作直接走分批 API，不尝试整体下载。

---

## 六、技术类陷阱（TECHnical）

### TECH-1 · 命令/编码污染
- **案例**：Python header 混入中文（UnicodeEncodeError）、bash 命令拼写错乱（cd 路径幻觉）；
- **规则**：代码块内（header/路径/变量名）禁止任何非 ASCII 字符；长命令先写脚本文件再执行。

### TECH-2 · 后台任务状态误判
- **案例**：多次 TaskOutput 空转轮询、被中断任务残留半成品文件（0 字节目录）；
- **规则**：后台任务重启前先清残留；下载类任务必查产物完整性（zip -t / json parse）。

## 七、前置检查规程（审计开始前 60 秒）

```
□ 本次审计对象层级？L0/L1/L2/L3（VER-3 标签）
□ 涉及「零依赖」断言？→ 三重扫清单先列好（RET-1）
□ 涉及方向/极限判断？→ 数值代点脚本先写（INT-1）
□ 外部常数/定理对照？→ 标注文献级/记忆级（CIT-1）
□ 将要下否定判定？→ 指明作用层级（VER-1）
□ 成本承诺？→ 三级分类 + 前提清单（COS-1）
□ 代码块全 ASCII？（TECH-1）
```

## 八、复核规程（审计完成后）

按本清单逐类回扫：RET-1/2/3（重跑容错检索）→ INT-1（重算数值）→ CIT-1（升级记忆级为文献级或标注）→ VER-1（红旗分层复核）→ 加分项双重验证（VER-2）。
