## 1. Stage 0 — 目标与前提显式化

| 子目标 | 内容 | 标注 | 说明 |
|---|---|---|---|
| S0.1 | 强 ACC 目标命题的自然语言表述 | B | 需确认「任意平衡平凡表示」中的「任意」「平衡」「平凡」是否按标准定义精确对应；机器只能做字符串/形式匹配，不能判定语义等价 |
| S0.2 | 强 ACC ↔ 正规闭包形式 ↔ sACC ↔ Zeeman 猜想的等价性转写 | B + C | 这是跨层映射：NL↔M↔M'。机器可生成候选形式化，但 **是否捕捉到同一个数学对象** 必须由人工判定；C 负责判定这些等价转写是否改变了问题类型 |
| S0.3 | 标记目标 P 在所有子目标证明环境中为 forbidden | M + H✓ | 机器可自动维护命名空间/上下文黑名单；人工需抽检黑名单是否意外遗漏等价表述 |

**Stage 0 人工总要求**：在构造开始前，人工必须签署「目标表述冻结声明」——所有后续子目标的 P 必须与此声明中的 P 等价。

## 2. Stage 1 — 反向草图（Backward Sketch）

| 路线 | 子目标 | 标注 | 人工必须做什么 | 机器可做什么 |
|---|---|---|---|---|
| G₁ 不变量 | G₁₁ 构造候选不变量 I | **A** | 提出不变量的数学形态（同调、低维表示、词统计、组合不变量等）；机器只能枚举已知不变量库，不能发明新数学对象 | 扫描文献/不变量数据库，给出候选列表及已知反例 |
|  | G₁₂ 证明 I 在 AC 变换下不变 | M + H✓ | 人工设计不变量定义后，机器可执行 AC1–AC3 的符号验证；但 **候选不变量是否值得验证** 是 A/C 判断 | 对给定 I 做 AC1/AC2/AC3 的保持性 diff |
|  | G₁₃ I(P)=I(P_triv) ⟹ P ~_AC P_triv | **C** | 判定该反向蕴含属于技术缺口还是本质缺口；若失败，需给出「无此类不变量」的元数学直觉 | 尝试用已知反例（AK 族）做黑箱测试 |
| G₂ 归纳 | G₂₁ 基例 n=1 | M + H✓ | 直接验证可由机器完成；人工抽检即可 | 枚举 n=1 平衡表示并验证 |
|  | G₂₂₁ 构造消去引理 | **A** | 核心概念奇点：是否存在从 n 元组中提取生成元的 AC 可计算操作？目前无已知构造 | 可尝试符号搜索短字长消去序列，但搜索失败 ≠ 不存在 |
|  | G₂₂₂ 归纳假设应用 | M + H✓ | 一旦 G₂₂₁ 闭合，机器可套用归纳壳 | — |
| G₃ Nielsen | G₃₁ 证明 Nielsen-等价于标准生成元 | M + D | Nielsen 约化算法可机械化；但 **该算法是否适用于关系元集合** 是 D（陷阱 V： premise-domain）审查 | 执行 Nielsen 约化，输出无法约化时的具体字 |
|  | G₃₂ Nielsen-等价 + 正规闭包条件 ⟹ AC-等价 | **B + C** | 判定两个等价关系的语义差异；这是跨层/跨关系比较，机器只能给出反例 | 搜索小字长反例（如 x²,y² 呈现） |
| G₄ 稳定化 | G₄₁ 证明 P 稳定 AC-平凡 | M + E | 对具体 P 可用机器搜索；对一般 P 需人工解读已知结果（AK(3) sACC 等） | 执行稳定化搜索；管理搜索下界 |
|  | G₄₂ 去稳定化引理 | **A + B + C** | A：发明构造性去稳定化方法；B：判定 sACC 与 ACC 的语义差距是否被桥接；C：若失败，定位是技术缺口还是本质缺口 | 枚举具体稳定序列，检查是否可去掉稳定化生成元 |
| G₅ 拓扑 | G₅₁ 将 P 关联到标准 2-复形 K_P | M + H✓ | 标准构造可机械化 | 自动构建 K_P 的胞腔结构 |
|  | G₅₂ 证明 K_P 简单同伦等价于一点 ⟹ P AC-平凡 | **B + C + E** | B：判定「简单同伦等价」与「AC 序列」是否语义同一；C：缺口刻画（Zeeman 猜想开放）；E：解读已有拓扑结果的可接受性 | 可计算低维复形同伦不变量，但不能判定一般可缩性 |

**Stage 1 人工总要求**：五条路线的草图发明（G₁、G₂₂₁、G₄₂ 的核心构造）全部由 A 完成；路线之间的等价性比较全部由 B+C 完成。

## 3. Stage 2 — 正向重写（Forward Rewriting）

| 子目标 | 标注 | 人工必须做什么 | 机器可做什么 |
|---|---|---|---|
| G₁ 候选 I 被 AC1/AC2/AC3 破坏 | M + H✓ | 人工确认机器给出的反例确实在目标数学语境下成立（B：反例是否忠于定义） | 对具体候选 I 做符号验证 |
| G₂ 基例 n=1 | M + H✓ | 抽检 | 枚举、验证 |
| G₂₂₁ 消去引理 | **A + C** | 若机器搜索失败，人工必须判定：失败是技术限制（搜索空间不够大）还是本质不可能（需数学论证）；这直接决定路线是否放弃 | 执行有界搜索；记录失败模式 |
| G₃ Nielsen 约化应用于关系元 | **D** | 审查 Nielsen 变换对关系元集合的前提域：Nielsen 操作生成元，AC 操作关系元——这是陷阱 V（premise-domain） | 在明确规则集下执行约化 |
| G₄₁ AK(3) 稳定化平凡序列 | M + E | 解读 Shehper et al. 2024 的结果：稳定化平凡 ≠ 标准平凡 | 可复现/验证公布的稳定序列 |
| G₅₂ 拓扑→AC | **B + E** | 判定「同伦等价」到「AC 序列」的跨层映射是否合法；机器不能做这个语义判定 | 计算具体复形的不变量 |

**Stage 2 关键纪律**：机器搜索失败时，必须生成 **honest sorry**，不能由机器自动换成「不存在」的结论（那是 E/C 的判断）。

## 4. Stage 3 — 双向验证（Bidirectional Check）

| 检查项 | 标注 | 说明 |
|---|---|---|
| 对每个闭合子目标 Gᵢ：A ∪ {closed Gⱼ} ⊢ Gᵢ | M + H✓ | 机器验证局部推导；人工抽检关键引理 |
| 对每个 Gᵢ：Gᵢ ⊬ P（目标） | **M + B** | 机器可检测命题等价性候选，但 **实质性等价**（substantial equivalence）必须由 B 判定；特别是 G₂₂₁ 消去引理与 ACC 的关系 |
| G₂₂₁ 消去引理 ⟹ ACC(n−1) 的双向性 | **C** | 必须人工判定该蕴含是否把目标 P 以等价形式偷偷引入前提；这是 C 的核心工作 |

**Stage 3 高危点**：G₂ 归纳中的消去引理。机器可能报告「未发现 G₂₂₁ 与 P 的语法等价」，但人工必须进一步判断它是否在语义上等价于目标（循环 3）。

## 5. Stage 4 — 等价循环探测（Cycle Detection）

| 循环候选 | 标注 | 机器可报 | 人工必须判定 |
|---|---|---|---|
| 循环 1：存在性 ⟹ 可找到性 | M + E | 机器可报「搜索未找到序列」 | E 解读 Bridson–Lishak 超指数下界：搜索失败不构成反例证据；D 审查 quantifier-range 陷阱 VI |
| 循环 2：sACC ⟹ ACC | M + C | 机器可标出「该蕴含正是开放问题」 | C 判定这是真正的外部开放问题，不是循环 |
| 循环 3：G₂₂₁ 消去引理 ⟺ ACC | **M + B + C** | 机器报告候选循环 | B 判定消去引理是否在语义上等价于目标；C 判定若等价，则该归纳路线本质循环，应放弃或重构 |

**Stage 4 总要求**：机器只做语法/形式等价扫描；所有「实质等价」判断归属 B，所有「是否放弃路线」归属 C。

## 6. Stage 5 — 边界扫描（Boundary Scan）

| 边界/陷阱类型 | 标注 | 人工动作 | 机器动作 |
|---|---|---|---|
| n=1 基例 | M + H✓ | 抽检 | 枚举 |
| n=2, 总长 ≤ 13 | M + E | 解读 Havas–Ramsay、Miasnikov、Shehper 等结果的可接受性 | 复现/验证已知平凡化序列 |
| AK(3) 标准 AC-平凡 | **D + C** | D：预见「搜索空间足够大但未找到」不等于「不存在」；C：刻画这是技术还是本质缺口 | 执行有界搜索；扩展搜索界限 |
| 超指数下界 ⟹ 搜索不可行 | **E** | 解读下界结果：排除纯搜索证明，但不排除结构证明 | — |
| 稳定化 vs 标准 AC（G₄） | **B + D** | B：判定两种变换语义是否同一；D：审查「sACC 成立」能否默认推广到「ACC 成立」（premise-domain 陷阱 V） | 枚举 sACC 序列并检查去稳定化可能性 |
| 拓扑 K_P 可缩 ⟹ AC-平凡（G₅） | **B + D** | B：判定同伦语言与 AC 语言的语义映射；D：审查「可缩」是否默认蕴含「简单同伦等价于点」 | 计算低维同伦不变量 |

**TRAP-CHECK v1.0 在 ACC 上的命中项**：
- VI.2 「是否把『没找到』当作『不存在』？」——命中 AK(3) 搜索。
- V.1 「规则在边界是否静默失效？」——命中 Nielsen→AC 桥接。
- VII.1 「多步操作是否改写为状态机？」——命中 AC 序列的逐步可验证性。

## 7. 按 SMPDL 角色汇总

### A — 概念奇点（必须人工发明）

| 位置 | 若缺失会怎样 |
|---|---|
| G₁₁ 非平凡 AC 不变量 | 整个 G₁ 路线无法启动 |
| G₂₂₁ 构造性消去引理 | G₂ 归纳路线阻塞 |
| G₄₂ 去稳定化算法/引理 | G₄ 无法从 sACC 升级到 ACC |
| （潜在）新的变换扩展集 | 若 ACC 本身不成立，可能需要修改问题 |

**判定标准**：如果子目标的产物是一个此前数学文献中没有的对象、且无法通过已知算法的有限组合得到，则它属于 A。

### B — 语义忠实审查（必须人工判定）

| 位置 | 风险 |
|---|---|
| 强 ACC ↔ 正规闭包形式 ↔ sACC ↔ Zeeman | 任何转写都可能悄悄改变问题 |
| Nielsen-等价 vs AC-等价 | 两者名称相近但数学内容不同 |
| 简单同伦等价 vs AC-序列 | 拓扑语言与组合语言的语义 gap |
| 消去引理 ↔ ACC 的实质等价 | 循环 3 的核心 |

**判定标准**：涉及两个不同表述是否「说同一件事」时，归属 B；机器只能做 diff，不能做忠实性裁决。

### C — 缺口刻画（必须人工分类）

| 位置 | 输出 |
|---|---|
| G₁ BLOCKED | 「无已知非平凡 AC 不变量」——类型：缺对象 |
| G₂ BLOCKED | 「消去引理非构造性」——类型：缺构造 / 潜在循环 |
| G₃ BLOCKED | 「变换集不等价」——类型：跨层映射失败 |
| G₄ PARTIAL | 「去稳定化引理缺失」——类型：缺中间桥梁 |
| G₅ BLOCKED | 「非构造性 + 仅覆盖稳定版」——类型：缺算法 + 语义范围不足 |

**判定标准**：面对未完成的开放问题，问「缺什么、缺口类型、下一步该找谁」时归属 C。

### D — 陷阱预见（必须人工扫描）

| 陷阱类型 | 在 ACC 中的体现 |
|---|---|
| V 前提域 | Nielsen 变换不适用于关系元；sACC 结论不自动适用于 ACC |
| VI 量词范围 | 搜索失败 ≠ 反例不存在 |
| VII 操作交互 | AC 序列中后续 move 可能破坏先前 move 的保护条件 |
| III 位置默认 | 不能默认「最短平凡化序列」存在即短；Bridson–Lishak 给出超指数下界 |

**判定标准**：面对已成形论证，问「哪里可能错」时归属 D。

### E — 验证解读（必须人工诠释）

| 验证输出 | 人工解读 |
|---|---|
| AK(3) 稳定 AC-平凡 | 只验证了 sACC，不等于 ACC |
| 总长 ≤ 13 的二生成元表示全部 AC-平凡 | 在已搜索范围内成立，不能推广到所有长度 |
| 机器搜索未找到 AK(3) 平凡化序列 | 由于超指数下界，这几乎不是证据 |
| 文献中 Borovik–Lubotzky–Myasnikov 的有限群结果 | 不能默认推广到无限自由群 |

**判定标准**：面对验证/搜索结果，问「这实际上证明了什么、多强」时归属 E。

## 8. 机器可全自动化的子任务清单

以下任务若输入规格明确，可交由机器/ATP 完成，人工只需抽检：

1. 对具体候选不变量 I 执行 AC1/AC2/AC3 保持性符号验证。
2. 枚举 n=1 和有限字长内的 n=2 平衡表示并验证 AC-平凡性。
3. 在固定字长/步长界限内搜索 AK(3) 的 AC 平凡化序列。
4. 维护依赖图并报告候选等价循环。
5. 对给定的关系元集合执行 Nielsen 约化（在明确规则下）。
6. 生成边界/退化测试用例（空表示、单生成元、自逆元等）。

## 9. 人工签收检查表（上传/提交前必读）

在把任何 ACC 构造成果提交给 SAIR 证明赛道或任何期刊前，必须逐项确认：

- [ ] **A1**：你是否提出了任何新的数学构造？若有，它是否已被同行结果排除？
- [ ] **B1**：你声称证明的是「标准 ACC」还是「稳定 ACC」？两者是否被明确区分？
- [ ] **B2**：你的形式化/符号表述与自然语言目标是否逐句对照？
- [ ] **C1**：每个 BLOCKED/PARTIAL 位置是否明确说明了缺口的类型（技术/本质/开放问题）？
- [ ] **C2**：你是否识别出任何等价循环？特别是归纳步骤是否隐含了目标本身？
- [ ] **D1**：你是否检查过「搜索失败 ⟹ 不存在」这一量词范围陷阱？
- [ ] **D2**：你是否检查过 Nielsen / AC / sACC 三者的前提域差异？
- [ ] **E1**：你引用的每个验证结果是否都被正确解读（稳定平凡 ≠ 标准平凡；有限搜索 ≠ 一般结论）？
- [ ] **H✓**：所有机器标记为 CLOSED 的子目标是否都有可审计的证据链？
