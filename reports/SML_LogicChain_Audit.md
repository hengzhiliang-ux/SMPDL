# SML 逻辑关系链审查可行性分析

> 回应提案：抛弃「依存图」，改为对 SML（语义 / 数学 / 逻辑）单独作「逻辑关系链」审查，链条断裂则失败。  
> 版本：v1.0 | 日期：2026-10-12 | 框架：Göttingen 数学史索引 · 同构分析章节

---

## 1. 核心结论（TL;DR）

**可以，但不建议完全替代。**

- **SML 逻辑关系链审查**是一种有效的**快速 PASS/FAIL 预检工具**，它把证明压缩为一条「语义陈述 → 数学形式 → 逻辑推导」的链条，链条中任一环节断裂即判定失败。
- 但它**不能取代** S*L / M*L / P*L 的**内生依存审查**，因为它会丢失三个关键信息：**断裂根因、修复方向、部分有效段落**。
- 最佳实践是：**先用 SML 链做粗筛，未通过直接失败；通过后，再用 S*L/M*L/P*L 依存图做定位审计**。
- **P（编程/形式化）层不应被完全抛弃**：即使 SML 链在纸上成立，P 层仍是唯一能给出「不可抵赖」确定性认证的环节。

---

## 2. 两种审查模式的精确定义

### 2.1 SML 逻辑关系链审查

把一份证明抽象为三条**串行链**：

```
S 链：自然语言命题 → 术语对齐 → 量词显式化 → 数学释义
        ↓
M 链：数学对象 → 公理/定义 → 引理/定理 → 目标命题
        ↓
L 链：前提集合 → 推理规则 → 中间结论 → 最终结论
```

**判定规则**：

- S 链断裂：自然语言无法忠实地翻译为数学命题。
- M 链断裂：数学对象之间缺少合法桥梁（如使用未证明的引理、结构不保持）。
- L 链断裂：从前提到结论的推理规则不合法（如肯定后件、循环论证、量词误用）。
- 任一链断裂 → **FAIL**。

### 2.2 S*L / M*L / P*L 内生依存审查

把证明拆成 S、M、P 三层，每层内部构建**有向依存图**，再检查层间映射是否闭合。

```
S 层元素 ──依存── S 层元素
    │                    │
    ↓ 翻译              ↓ 翻译
M 层元素 ──依存── M 层元素
    │                    │
    ↓ 形式化            ↓ 形式化
P 层元素 ──依存── P 层元素
```

**判定规则**：

- 每层内部：依赖链是否闭合？是否有悬空节点？是否有循环？
- 层间映射：S→M、M→P 的翻译是否保持依赖关系？
- 输出：**断裂位置 + 缺失条件 + 修复建议**。

## 3. 两种模式的对比

| 维度 | SML 逻辑关系链 | S*L/M*L/P*L 内生依存审查 |
|---|---|---|
| **粒度** | 粗：只判断每层是否通 | 细：能指出具体哪个元素、哪条依赖断裂 |
| **输出** | PASS / FAIL（+ 断裂层） | 断裂位置、缺失条件、修复方向 |
| **自动化难度** | 中（可用 LLM 快速判断） | 高（需结构化解析/形式化工具） |
| **对错误证明的敏感性** | 高（链断即死） | 高（且能定位） |
| **对近似/启发式证明的容忍度** | 低（容不下「几乎成立」） | 中（可标记部分有效段落） |
| **修复成本** | 高（只能知道某层失败，不知如何修） | 低（直接指向缺失前提或非法跳跃） |
| **与形式化核的衔接** | 弱 | 强（P*L 直接产生 `sorry`/报错） |
| **用户心智负担** | 低（只有三条链） | 高（三张图 + 层间映射） |

**关键差异**：SML 链回答「哪一层死了」；依存图回答「死在哪里、为什么死、怎么救」。

## 4. SML 链的三种断裂模式

### 4.1 S → M 断裂：翻译失败

**表现**：自然语言陈述无法唯一、忠实地映射到数学命题。

**例子**：

- 「充分大的 n」未给出量词范围。
- 「由对称性类似可得」未说明是哪种对称。
- 隐喻（如「零点像能级」）无形式化对应。

**SML 判定**：S 链断裂 → FAIL。

**依存审查补充**：会生成「术语映射表」中缺失的条目，并指出具体哪个术语未对齐。

### 4.2 M → L 断裂：推理失败

**表现**：数学命题本身合法，但从前提到结论的推导不成立。

**例子**：

- 从「几乎所有轨道有界」跳到「所有轨道有界」（Collatz）。
- 把函数域结果直接套用到数域（RH、abc）。
- 用等价引理证明原命题（循环/等价证明）。

**SML 判定**：M/L 链断裂 → FAIL。

**依存审查补充**：会标出具体从哪个数学对象到哪个对象的依赖非法，以及缺失的数学条件。

### 4.3 L → 结论断裂：结论过强

**表现**：逻辑推导有效，但结论超出了前提允许的范围。

**例子**：

- 在等腰三角形谬误中，局部图成立，但结论「所有三角形等腰」过强。
- 用「rank 1」的 BSD 结果推出所有椭圆曲线。

**SML 判定**：L 链断裂 → FAIL。

**依存审查补充**：会指出结论依赖的某个全称量词或全域推广未获支持。

## 5. 为什么不能完全抛弃 P 层

用户提案中隐含「SML」而 dropping P。需要单独说明：

| 层级 | 在 SML 链中 | 在依存审查中 | 不可替代的理由 |
|---|---|---|---|
| **P（编程/形式化）** | 被忽略 | 作为第三层与 L 内生依存 | 提供**机械确定性**：Lean/Coq 内核要么接受、要么留下 `sorry`。SML 链无法给出同等强度的认证。 |

**最小化方案**：

- 如果资源受限，可把 P 层作为**可选强化步骤**，只在 SML 链通过后运行。
- 但即使这样，也不能说「P 不重要」——只能说「本次未执行」。

## 6. 推荐混合工作流

```text
Step 0: 输入证明
    │
    ▼
Step 1: SML 逻辑关系链快速审查（低成本预筛）
    ├── S 链断裂 → 退回重写自然语言
    ├── M 链断裂 → 进入 M 层审计
    ├── L 链断裂 → 进入 L 层审计
    └── 三链均通过 → Step 2
    │
    ▼
Step 2: S*L / M*L / P*L 依存图定位审计（高成本精确定位）
    ├── 元素提取
    ├── 依存图构建
    ├── 闭合性审查
    └── 输出：断裂位置 + 缺失条件 + 修复建议
    │
    ▼
Step 3: 修复后重新进入 Step 1
    │
    ▼
Step 4: 可选 P 层形式化验证（Lean/Coq）
```

**原则**：SML 链负责**快速失败**，依存审查负责**精确修复**。

## 7. 快速示例：等腰三角形谬误

用 SML 链审查 Rouse Ball「所有三角形都是等腰」证明。

### 7.1 S 链

| 环节 | 内容 | 状态 |
|---|---|---|
| 自然语言命题 | 「所有三角形都是等腰」 | ✅ 可翻译 |
| 术语对齐 | 垂直平分线、角平分线、全等 | ✅ 对齐 |
| 量词显式化 | ∀ 三角形 ABC, AB = AC | ✅ 可显式化 |
| 数学释义 | 几何命题 | ✅ 闭合 |

**S 链：PASS**

### 7.2 M 链

| 环节 | 内容 | 状态 |
|---|---|---|
| 数学对象 | 三角形、点 P、垂足 U/V、距离 | ✅ 合法 |
| 公理/定义 | 垂直平分线性质、角平分线性质、RHS 全等 | ✅ 可用 |
| 引理/定理 | 直角三角形全等 → 对应边相等 | ✅ 合法 |
| 目标命题 | AC = BC | ⚠️ 推导中使用了未声明条件 |

**M 链：FAIL**（在「长度加法分解 AC = AU + CU」处断裂，缺少 U 在 AC 内部的条件）

### 7.3 L 链

| 环节 | 内容 | 状态 |
|---|---|---|
| 前提 | PA=PB, PU=PV, 两组 RHS 全等 | ✅ 成立 |
| 推理规则 | 等式传递、长度加法 | ⚠️ 加法公式非法推广 |
| 中间结论 | AU = BV, CU = CV | ✅ 成立 |
| 最终结论 | AC = BC | ❌ 不成立 |

**L 链：FAIL**（从中间结论到最终结论的推理在非等腰三角形中不合法）

### 7.4 SML 链结果

- **整体：FAIL**
- **断裂层**：M 链 + L 链
- **但无法直接回答**：具体缺失哪个几何条件。

### 7.5 与依存审查对比

S*L/M*L/P*L 依存审查能明确指出：

```
S8:  AC = AU + CU    依赖    U 在线段 AC 内部（未声明）
M9:  长度加法分解    依赖    on-segment 条件（非普遍成立）
P11: dist A C = dist A U + dist U C    在 Lean 中无法证明（缺少 between A U C）
```

**结论**：SML 链能判死，但依存审查能给出「死因报告」。

## 8. 何时可以只用 SML 链？

以下场景可以**临时**使用 SML 链作为简化方案：

| 场景 | 理由 |
|---|---|
| 资源受限（低模型上限、无形式化环境） | SML 链比完整依存审查更轻量。 |
| 快速预筛大量候选证明 | 先剔除明显有问题的，再对通过者做深度审计。 |
| 教学/演示场景 | 三条链更直观，适合向非技术用户解释。 |
| 已知模式化的错误证明 | 如循环论证、量词混淆，SML 链已足够。 |

**但即使在这些场景，也应在报告中标明**：「本结果为 SML 链粗筛，未执行 S*L/M*L/P*L 精确定位审计。」

## 9. 对 Göttingen 项目的建议

1. **不要把 SML 链写成「替代」关系**，而应写成「前置快速过滤器 + 失败触发器」。
2. **在 SMP_Isomorphism_Checklist.md 中新增一节「快速审查：SML 链」**，放在完整依存审查之前。
3. **保留 P 层作为可选强化**，而不是删除。
4. **在 Göttingen 页面方法论弹窗中**：
   - 低配模式下展示 SML 链（三条链 + PASS/FAIL）。
   - 高配模式下才展开为 S*L/M*L/P*L 依存图。
5. **在证明审校系统提示词中**：要求先输出 SML 链判定，若 FAIL 则停止；若 PASS 再继续输出依存图。

---

## 10. 结论

> **可以抛弃完整的依存图审查而单独使用 SML 逻辑关系链，但代价是只能知道「失败」，而不知道「失败在哪里」和「如何修复」。**

推荐采用「SML 链快速失败 + S*L/M*L/P*L 依存图精确定位」的**双层审查架构**。SML 链是高效的粗筛网，依存图是精准的手术刀。两者不是互斥，而是互补。
