# 逻辑结构审查的附加条件清单

> 回答：除了「内生依存关系」，完整的 L（逻辑/结构）层审查还需要补齐哪些条件？  
> 版本：v1.0 | 日期：2026-10-12 | 框架：Göttingen 数学史索引 · 同构分析章节

---

## 1. 核心结论

内生依存关系只是逻辑结构审查的**骨架**。要使审查完整，至少还需要补齐以下六个维度：

| 维度 | 核心问题 | 审查目标 |
|---|---|---|
| **1. 量词纪律** | 量词范围、顺序、论域是否合法？ | 防止 ∀∃ / ∃∀ 混淆、域外应用 |
| **2. 假设管理** | 每个结论依赖哪些假设？假设是否被正确引入/消解？ | 防止未消解假设、循环论证、偷换前提 |
| **3. 推理规则合法性** | 每一步是否使用了有效的推理规则？ | 防止肯定后件、否定前件、非法概括 |
| **4. 结构完整性** | 证明结构（定义/引理/定理/推论）是否闭合？ | 防止遗漏分支、未覆盖边界 |
| **5. 边界与反例敏感性** | 结论在边界情况下是否仍成立？ | 防止把特例推广为全称 |
| **6. 元逻辑卫生** | 语言层次是否清晰？是否混淆对象层与元层？ | 防止自指、无穷回归、非法元论证 |

这些条件与「内生依存」不是并列关系，而是**对依存链的逐节点体检**——依存图告诉你「谁依赖谁」，这些条件告诉你「依赖本身是否合法」。

---

## 2. 维度一：量词纪律（Quantifier Discipline）

### 2.1 检查点

- [ ] **论域明确**：每个量词是否指定了论域？（如「对所有实数 x」「对任意素数 p」）
- [ ] **量词顺序合法**：`∀x ∃y` 与 `∃y ∀x` 是否被正确区分？
- [ ] **实例化合法**：从 `∀x P(x)` 推出 `P(c)` 时，c 是否在论域内？
- [ ] **概括合法**：从 `P(c)` 推出 `∀x P(x)` 时，c 是否为任意/新鲜的？
- [ ] **存在消去合法**：从 `∃x P(x)` 引入代表元时，是否确保其不依赖于其他自由变量？

### 2.2 常见错误模式

| 错误 | 例子 |
|---|---|
| **∀∃ 混淆** | 「对任意 ε，存在 δ」被错误地理解为「存在一个 δ 适用于所有 ε」。 |
| **论域外实例化** | 从「所有自然数 n，n≥0」推出「-1 ≥ 0」。 |
| **概括过强** | 从「对某个素数 p，p>10」推出「所有素数都大于 10」。 |
| **存在代表元污染** | `∃n P(n)` 引入的 `n₀` 随后又用于推导依赖于外部参数的公式。 |

### 2.3 与 SML 链的对应

- **S 层**：自然语言中的「所有」「某个」「任意」是否对应正确的量词？
- **M 层**：量词结构是否保持了数学命题的精确含义？
- **L 层**：量词规则应用是否合法？

---

## 3. 维度二：假设管理（Hypothesis Management）

### 3.1 检查点

- [ ] **假设显式化**：每个结论是否清楚标注了依赖的前提？
- [ ] **假设可消解**：通过反证法或条件证明引入的临时假设，是否在结论前正确消解？
- [ ] **无游离假设**：最终定理的结论是否不再依赖未消解的临时假设？
- [ ] **无假设污染**：一个子证明的本地假设是否被非法带入另一个子证明？
- [ ] **前提最小化**：结论是否使用了比所需更多的前提？（非错误，但需记录）

### 3.2 常见错误模式

| 错误 | 例子 |
|---|---|
| **循环论证** | 用目标结论的弱化形式来证明目标本身。 |
| **未消解假设** | 反证法中假设了 `¬P`，推出矛盾后忘记得出结论 `P`。 |
| **假设污染** | 子证明 A 中临时假设 `a>0` 被偷偷用于子证明 B。 |
| **等价循环** | 用与原命题等价的引理来证明原命题，但未意识到等价性。 |

### 3.3 与依存审查的关系

依存图能发现「A 依赖 B」，但**假设管理**能发现「A 对 B 的依赖是非法的」（例如 B 本身还依赖于 A，或 B 是未消解的临时假设）。

## 4. 维度三：推理规则合法性（Rule Legitimacy）

### 4.1 检查点

- [ ] **肯定前件（Modus Ponens）**：从 `A → B` 和 `A` 推出 `B`。
- [ ] **否定后件不成立**：从 `A → B` 和 `¬B` 推出 `¬A`（这才是有效的 Modus Tollens），而不是从 `A → B` 和 `¬A` 推出 `¬B`。
- [ ] **析取三段论**：从 `A ∨ B` 和 `¬A` 推出 `B`。
- [ ] **等式替换**：替换是否在等式适用的上下文中进行？
- [ ] **归纳法结构**：基例、归纳假设、归纳步骤是否完整？
- [ ] **反证法结构**：是否从 `¬P` 推出矛盾，从而得到 `P`？

### 4.2 常见错误模式

| 错误 | 名称 | 例子 |
|---|---|---|
| 从 `A → B` 和 `B` 推出 `A` | 肯定后件（Affirming the Consequent） | 「如果下雨则地湿；地湿了，所以下雨了。」 |
| 从 `A → B` 和 `¬A` 推出 `¬B` | 否定前件（Denying the Antecedent） | 「如果下雨则地湿；没下雨，所以地不湿。」 |
| 从 `A → B` 推出 `B → A` | 逆命题错误 | 「如果 n 是素数则 n>1；所以 n>1 则 n 是素数。」 |
| 从 `A → C` 和 `B → C` 推出 `A → B` | 非法传递 | 混淆充分条件与必要条件。 |

### 4.3 与 Lean/P 层的对应

在 Lean 中，非法推理规则通常表现为：

- `apply` 失败，因为目标与结论不匹配。
- `intro`/`cases` 后留下未解决目标。
- `by_contra` 后未从矛盾推出原命题。

## 5. 维度四：结构完整性（Structural Integrity）

### 5.1 检查点

- [ ] **定义前置**：所有使用的术语是否已在证明前定义？
- [ ] **引理可调用**：所有引理是否已被证明或明确引用？
- [ ] **分支覆盖**：分情况讨论是否穷尽所有可能？
- [ ] **链式等式合法**：`a = b = c = d` 中每一步是否都有合法依据？
- [ ] **全称推广完整**：从特例推广到全称前，是否验证了任意性？
- [ ] **子证明隔离**：每个引理/子证明的输入输出是否清晰？

### 5.2 常见错误模式

| 错误 | 例子 |
|---|---|
| **遗漏分支** | 证明「所有整数 n，n² ≥ n」时只考虑 n≥1，遗漏 n≤0。 |
| **未定义术语** | 使用「充分大」但未给出 N 的定义。 |
| **链式跳跃** | `AC = AU + CU = BV + CV = BC` 中某一步缺少几何条件。 |
| **子证明泄漏** | 引理内部使用的特殊假设被主证明继承。 |

### 5.3 与依存审查的关系

依存图能发现「某个元素没有前驱」，而结构完整性审查能发现「虽然有前驱，但前驱集合不穷尽」。

---

## 6. 维度五：边界与反例敏感性（Boundary & Counterexample Awareness）

### 6.1 检查点

- [ ] **零/空/退化情况**：是否考虑了空集、零元、退化图形、平凡群等？
- [ ] **无穷/发散情况**：极限、无穷级数、无穷集合的处理是否合法？
- [ ] **否定/反例测试**：结论是否有已知的反例？证明是否排除了反例成立的条件？
- [ ] **连续/离散差异**：在连续域中成立的步骤是否在离散域中仍成立？反之亦然。
- [ ] **维度/规模变化**：低维证明推广到高维时是否需要额外条件？

### 6.2 常见错误模式

| 错误 | 例子 |
|---|---|
| **零除** | 证明中除以 x 但未排除 x=0。 |
| **空真全称** | 对空集使用全称命题，结论看似成立但无实质内容。 |
| **把近似当精确** | 数值验证到很大范围后声称对所有成立。 |
| **退化图形** | 几何证明中假设三角形非退化但未声明。 |

### 6.3 与 SML 链的对应

- **S 层**：自然语言是否暗示了边界条件（如「三角形」是否包含退化三角形）？
- **M 层**：边界对象是否属于数学论域？
- **L 层**：推理规则在边界情况下是否仍有效？

---

## 7. 维度六：元逻辑卫生（Metalogical Hygiene）

### 7.1 检查点

- [ ] **对象层 vs 元层**：是否混淆了「命题 P 为真」与「『P』这个字符串可被证明」？
- [ ] **系统内 vs 系统外**：是否用元数学事实（如哥德尔定理）在系统内推导结论？
- [ ] **自指控制**：证明中是否出现了未受控的自指或无穷回归？
- [ ] **公理一致性**：引入的新公理是否与已有公理一致？是否必要？
- [ ] **构造性/经典性**：是否明确使用了排中律、选择公理等非构造性原则？

### 7.2 常见错误模式

| 错误 | 例子 |
|---|---|
| **系统外论证入侵** | 用「哥德尔不完备定理说明该命题不可判定」来支持/反对证明。 |
| **自指循环** | 构造「这个命题不可证」式的语句来推导结论。 |
| **混淆证明与真理** | 因为「没有已知证明」而推出「不成立」。 |
| **隐蔽选择公理** | 使用无限选择但未声明依赖 AC。 |

### 7.3 与 P 层的对应

在 Lean 中，元逻辑问题常表现为：

- `#print axioms theorem_name` 显示依赖了未声明的公理。
- 使用 `Classical.choice` 导致计算内容丢失。
- 将元数学定理（如不可判定性）作为对象级引理使用。

## 8. 附加条件与内生依存审查的整合

### 8.1 每个依存节点都需要回答的六个问题

对于依存图中的每一条边 `A → B`（A 支持 B），都要问：

| 问题 | 对应维度 |
|---|---|
| A 是否在 B 的量词论域内？ | 量词纪律 |
| A 是否为 B 的未消解假设？ | 假设管理 |
| 从 A 到 B 的推理规则是否有效？ | 推理规则合法性 |
| A 是否覆盖了 B 所需的所有分支/情况？ | 结构完整性 |
| A 在边界情况下是否仍成立？ | 边界与反例 |
| A 是否处于正确的逻辑层次？ | 元逻辑卫生 |

### 8.2 与 SML 链的对应

| SML 链环节 | 主要附加条件 |
|---|---|
| **S 链** | 量词纪律（术语对应量词）、结构完整性（术语定义）、元逻辑卫生（隐喻 vs 形式） |
| **M 链** | 量词纪律（论域）、结构完整性（分支覆盖）、边界与反例 |
| **L 链** | 假设管理、推理规则合法性、元逻辑卫生 |

## 9. 对 Göttingen 项目的建议

### 9.1 检查清单升级

在 `SMP_Isomorphism_Checklist.md` 的 L 层部分，除了「依存图」外，增加以下检查清单：

```markdown
## L 层：证明逻辑结构审查

### 9.1 内生依存关系
- [ ] 元素提取完整
- [ ] 依存图无悬空节点
- [ ] 依存图无循环
- [ ] 层间映射保持依赖关系

### 9.2 量词纪律
- [ ] 论域明确
- [ ] 量词顺序正确
- [ ] 实例化/概括合法

### 9.3 假设管理
- [ ] 假设显式化
- [ ] 临时假设正确消解
- [ ] 无假设污染

### 9.4 推理规则合法性
- [ ] 无肯定后件/否定前件
- [ ] 归纳/反证法结构完整
- [ ] 等式替换上下文合法

### 9.5 结构完整性
- [ ] 定义/引理前置
- [ ] 分支覆盖穷尽
- [ ] 全称推广前验证任意性

### 9.6 边界与反例
- [ ] 零/空/退化情况已处理
- [ ] 无穷/发散情况合法
- [ ] 结论对已知反例不敏感

### 9.7 元逻辑卫生
- [ ] 对象层/元层区分清晰
- [ ] 新公理一致且必要
- [ ] 构造性/经典性原则已披露
```

### 9.2 提示词升级

在 Göttingen 证明审校系统提示词中，除了要求输出依存图，还应要求：

> "对依存图中每条边，额外标注是否存在量词、假设、推理规则、结构覆盖、边界条件、元逻辑六个维度的问题。"

### 9.3 UI 展示

在方法论弹窗的 L 层部分，除了「依存关系」，增加「逻辑纪律」小节，用表格展示六个维度及其常见 red flags。

## 10. 结论

> **内生依存关系是逻辑结构审查的骨架，但仅有骨架不够。**

完整的 L 层审查需要同时检查：
1. **量词纪律**
2. **假设管理**
3. **推理规则合法性**
4. **结构完整性**
5. **边界与反例敏感性**
6. **元逻辑卫生**

这六个维度回答了「依存关系本身是否合法」。建议将 L 层审查升级为「**依存图 + 逻辑纪律**」的双轨模式，并在 Göttingen 的检查清单、提示词、UI 中同步体现。
