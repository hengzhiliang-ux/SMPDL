# 防前视证明构建流程：S/M/P × D/L 正向构建纪律

> 目标：把审计框架反过来用，建立一套**构造证明时防止前视**的工作流。  
> 版本：v1.0 | 日期：2026-10-12 | 框架：Göttingen S/M/P × D/L

---

## 1. 核心问题：什么是「前视」

**前视（foresight / hindsight bias）**指写证明的人已经知道结论，于是在中间步骤里不自觉地：

- 挑选性地使用假设，跳过本需单独验证的引理；
- 把「为了让结论成立所需的条件」悄悄当作已知；
- 用结论本身或其等价形式来「润滑」推理；
- 在边界/退化情形下默认结论仍然成立。

这不是简单的计算错误，而是**方向性错误**：证明的叙述从结论出发，而不是从前提出发。

---

## 2. 基本策略：反向草稿 + 正向重写

真正的数学发现往往是**反向**的：从目标 P 倒推，问「要证 P，只需证什么？」但呈现的正式证明必须是**正向**的：从前提 A 出发，合法地推出 P。

因此流程分为两步：

| 阶段 | 允许做什么 | 产出物 | 风险 |
|---|---|---|---|
| **反向草图** | 从 P 倒推子目标 | 子目标树（subgoal tree） | 容易把子目标当已知 |
| **正向重写** | 从前提出发，逐条证明每个子目标 | 正向证明链 | 容易跳过连接点 |

**关键纪律**：反向草图里的每个节点都必须被重新标记为 **⊢ 待证（open subgoal）**，然后在正向重写中独立闭合。

## 3. S/M/P × D/L 正向构建流程

### 3.0 准备工作：目标与前提显式化

在动笔之前，先填三张卡：

```
命题卡
目标 P：_______________________________
量词结构：∀ / ∃ / 某个 / 有限 / 无限：__________
论域：_________________________________
结论类型（等式/不等式/存在性/全称性）：__________

前提卡
已知 A：_______________________________
可用定义：_____________________________
可用公理/引理（须编号）：_______________
禁止使用的（含等价形式）：_____________

反向草图卡
要证 P，只需证 G₁
要证 G₁，只需证 G₂
...
要证 Gₙ，只需证 A（或可用引理）
```

### 3.1 S 层构建：语义 → 主张-理由对

S 层负责把自然语言证明拆成**不可再缩小的主张-理由对**。

**构建纪律**：

1. 每个段落只写一个主张；
2. 主张后面紧跟理由，理由必须是**已证命题**或**显式引用的公理/定义**；
3. 禁止出现「由对称性」「类似可得」「显然」等未显化的理由；
4. 每个「因为」必须指向**此前**出现过的对象。

**前视检测**：

- 若某个理由指向的是**后面才出现**的结论或子目标 → 🔴 前视
- 若某个理由没有明确来源 → 🟡 隐性问题
- 若某个段落的表述类似「由于 P 成立，所以……」而 P 正是目标 → 🔴 循环

### 3.2 M 层构建：数学对象 → 正向推导图

M 层负责建立**数学对象和定理之间的正向依赖图**。

**构建纪律**：

1. 列出所有中间对象（集合、映射、不变量、界、函数等）；
2. 每个对象必须有**构造规则**：从前提出发，如何得到它；
3. 每个引理必须有**独立证明**，不能因为它「帮助证明 P」而被假设；
4. 依赖图必须是从 A → P 的 DAG，禁止指向 P 的反向边。

**前视检测**：

- 依赖图中出现从 P 到中间节点的边 → 🔴 循环论证
- 某条边的理由是「P 需要它」而不是「A 能推出它」 → 🔴 目的论推理
- 某个不变量没有在前面的对象中定义 → 🟡 悬空对象

### 3.3 P 层构建：形式化骨架 → 可填充的 holes

P 层负责把证明写成 Lean/Coq 风格的**定理骨架**。

**构建纪律**：

1. 先写 `theorem P : ... := by` 和 `sorry`；
2. 把 `sorry` 逐步替换为 `have` 或 `apply`；
3. 每个 `have` 必须带类型和证明体；
4. 证明体不允许包含未完成的 `sorry`，除非该引理被标记为「外部引理」并列出。

**前视检测**：

- `have` 的类型正好是 P 或 P 的等价形式 → 🔴 等价循环
- `apply` 的目标在上下文中无法由前提推出 → 🟡 非法反向
- 某个 `have` 没有独立证明体 → 🟡 子目标未闭合

## 4. D/L 实时检查：构建过程中的自审

### 4.1 D 层：依赖闭合检查

每写一步，问三个问题：

1. **它依赖谁？** 列出直接前驱。
2. **谁依赖它？** 确认后续步骤不把它当已知。
3. **是否闭合？** 所有直接前驱都在前提、公理或已证步骤中。

**前视检测**：

- 某步骤的直接前驱包含目标 P 或其后继子目标 → 🔴
- 某步骤的直接前驱来自「反向草图」但未经验证 → 🟡

### 4.2 L 层：逻辑合法性检查

每写一步，问六个问题（对应六维逻辑纪律）：

| 维度 | 检查 |
|---|---|
| 量词纪律 | 这步的论域、量词顺序、实例化是否合法？ |
| 假设管理 | 新引入的假设是否在子证明末尾正确消解？ |
| 推理规则 | 这步是 MP、泛化、特化、归纳、反证中的哪一种？是否合法？ |
| 结构完整性 | 定义是否前置？子证明是否隔离？ |
| 边界与反例 | 这步在零、空、退化、无穷情况下是否仍成立？ |
| 元逻辑卫生 | 是否混淆对象层与元层？是否用等价命题循环证明原命题？ |

**前视检测**：

- 量词实例化时选了一个「恰好让结论成立」的特殊对象 → 🔴
- 反证法中假设 ¬P 后推出 P → 🔴（除非通过矛盾）
- 边界情况被默认跳过 → 🟡

## 5. 防前视核心机制

### 5.1 子目标隔离墙

反向草图中产生的每个子目标 Gᵢ 必须：

- 在正向重写时**重新声明**为待证；
- 不能因为它的「后代」能推出 P 而获得信任；
- 必须有独立的正向证明，且该证明不引用 P。

### 5.2 双向验证

每个中间命题 Q 必须接受双向检查：

- **正向**：A ⊢ Q 是否成立？
- **反向**：Q ⊢ P（或更接近 P 的子目标）是否成立？

只有当 Q 能同时通过正向和反向验证时，它才被允许作为中间节点。

### 5.3 等价循环探测器

禁止以下模式：

```
要证 P。
引理 Q，其中 Q ↔ P。
由 Q 得 P。证毕。
```

除非 Q 是**公认的已证定理**，否则这就是等价循环。

检测方法：列出每个 `have` 的类型，检查其中是否有 P 的等价命题。

### 5.4 边界扫描清单

在证明主体完成后，强制扫描：

- 论域是否为空？
- 是否有除以零、零测集、空交集？
- 退化情形（如 n=1, 空图, 平凡群）是否单独处理？
- 无穷/极限情形是否与有限情形统一处理？

## 6. 工作流程图

```
开始
  │
  ▼
[0] 显式化：目标 P、前提 A、可用工具
  │
  ▼
[1] 反向草图：从 P 生成子目标树 G₁, G₂, ..., Gₙ
  │           （所有节点标记为 OPEN）
  ▼
[2] 正向重写：从前提出发，逐条闭合 Gₙ, ..., G₂, G₁
  │           每步通过 S/M/P × D/L 检查
  ▼
[3] 双向验证：每个 Gᵢ 同时满足 A→Gᵢ 和 Gᵢ→P
  │
  ▼
[4] 等价循环探测：检查没有 have 是 P 的等价命题
  │
  ▼
[5] 边界扫描：零、空、退化、无穷情况
  │
  ▼
[6] 最终连接：正向链末端 = P
  │
  ▼
结束
```

## 7. 与审计流程的对应关系

| 构建阶段 | 对应审计项 | 作用 |
|---|---|---|
| [0] 显式化 | S*D / S*L | 明确语义与量词 |
| [1] 反向草图 | M*D（逆向） | 发现依赖结构，但不允许作为正向依据 |
| [2] 正向重写 | M*D / M*L | 建立合法正向依赖图 |
| [3] 双向验证 | 跨层 D/L 映射 | 保证中间节点不是凭空产生 |
| [4] 等价循环探测 | M*L / P*L | 防止循环论证 |
| [5] 边界扫描 | M*L | 防止隐藏反例 |
| [6] 最终连接 | P*D / P*L | 形式化闭合 |

## 8. 快速示例：证明「√2 无理」的防前视构建

### 8.1 显式化

- **目标 P**：√2 是无理数。
- **前提 A**：自然数、整数、有理数定义；gcd 基本性质；素数定义；奇偶性。
- **可用引理**：若 a² 偶，则 a 偶。
- **禁用**：「√2 不是分数」（即 P 本身）。

### 8.2 反向草图

```
P: √2 无理
  G₁: 假设 √2 = p/q（最简），推出矛盾
    G₂: p² = 2q²
    G₃: p² 偶 ⇒ p 偶
    G₄: p = 2k ⇒ 4k² = 2q² ⇒ q² = 2k²
    G₅: q² 偶 ⇒ q 偶
    G₆: p, q 同时偶，与最简矛盾
```

### 8.3 正向重写

1. **假设**：设 √2 = p/q，其中 p, q ∈ ℤ，q ≠ 0，gcd(p,q)=1。（引入假设，标记为 H）
2. **平方**：2 = p²/q² ⇒ p² = 2q²。（合法代数运算，依赖 H）
3. **应用引理**：p² 偶 ⇒ p 偶。（依赖引理与 G₂，G₂ 已证）
4. **设 p = 2k**：代入得 4k² = 2q² ⇒ q² = 2k²。（依赖 G₃）
5. **应用引理**：q² 偶 ⇒ q 偶。（依赖 G₄）
6. **矛盾**：p, q 均为偶，与 gcd(p,q)=1 矛盾。（依赖 G₃、G₅、H）
7. **结论**：√2 无理。（反证法，依赖 H 导出矛盾）

### 8.4 防前视检查

- **S 层**：每个理由都指向前置步骤，无「因为 √2 无理」类表述 ✅
- **M 层**：依赖图从 H → G₂ → G₃ → G₄ → G₅ → G₆ → P，无反向边 ✅
- **P 层**：每个 `have` 都有独立证明体，无 `sorry` ✅
- **D 层**：每步前驱都已闭合 ✅
- **L 层**：反证法假设在子证明末尾通过矛盾消解；q ≠ 0 边界已显式；gcd(p,q)=1 是最简化的合法性来源 ✅

## 9. 与 Lean/Coq 的对应

| 构建纪律 | Lean/Coq 对应 |
|---|---|
| 子目标隔离墙 | `have` / `suffices` 独立作用域 |
| 双向验证 | 类型检查 + 目标匹配 |
| 等价循环探测 | 禁止 `have h : P` 的证明体中出现 P |
| 边界扫描 | `cases` / `by_cases` 穷举 |
| 最终连接 | `exact` / `apply` 闭合主目标 |
